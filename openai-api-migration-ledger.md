# Журнал изменений AI-интеграции

**Приложение:** support_MAS — Telegram support bot, FastAPI, SQLite, FAISS.

**Текущие вызовы:** Chat Completions и embeddings `text-embedding-3-small` через общий пул асинхронных OpenAI-compatible клиентов для OpenAI или ProxiAPI.

**Модель ответов:** `gpt-4.1-mini`; в текущей официальной документации модель отмечена устаревающей. Модель не меняется в этом объёме; перед публичным запуском проверить сроки доступности и согласовать преемника.

**Сценарии:** ответы Telegram, query embeddings для RAG, embeddings аналитики; админский тестовый запрос. Инструментов и потоковой выдачи нет.

**Объём:** повысить надёжность клиентов, единообразно применять выбранного провайдера, обрабатывать сетевые ошибки и отмену; сохранить существующую модель, провайдеры, Chat Completions, текстовый формат ответа и ограничения токенов. Responses API миграция пока не входит в утверждённый объём: ProxiAPI совместимость не подтверждена, а текущий пользовательский запрос — стабилизация пилота.

**Порядок:** (1) единый lifecycle и провайдер для AI/embeddings; (2) устойчивый обработчик сообщений и аналитика вне критического пути; (3) безопасное общее состояние RAG; (4) подготовленные, но выключенные настройки Jivo; (5) безопасность и чистый запуск; (6) проверочный набор из предоставляемого пользователем Excel — ожидает файл. Подробные этапы согласованы в чате.

**Данные и приватность:** приложение хранит историю последних двух пар сообщений в памяти отдельно по паре Telegram chat/user, а вопросы и embeddings аналитики — в SQLite. В AI API отправляются текст вопроса, RAG-контекст и история. Новое серверное состояние Responses, кэширование приложения и срок удержания внешних данных не вводятся. Отдельное требование ZDR / региональной обработки пользователь не задавал; обработка внешним AI-провайдером зависит от проекта и выбранного маршрута.

**Проверки:** локальные проверки и тесты с mock-клиентами; реальные платные вызовы и боевой бот не запускались. Полный набор вопросов ожидает Excel.

## Оценка рекомендаций Responses API

Документация OpenAI рекомендует Responses API для новых text-generation интеграций. `gpt-4.1-mini` поддерживает оба endpoint, но в текущем каталоге моделей помечена как deprecated. Responses API и смена модели не входят в согласованный объём пилотной стабилизации. Для ProxiAPI совместимость Responses endpoint не подтверждена, а для новой модели нужен пользовательский Excel-набор для сравнения качества. Сохранить текущий Chat Completions маршрут и модель в этом изменении; согласовать дальнейший переход после оценки на Excel и подтверждения совместимости ProxiAPI. Источники: https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://developers.openai.com/api/docs/models/gpt-4.1-mini .

## Принятые решения и валидация

- Сохранить `gpt-4.1-mini`, Chat Completions и оба провайдера в рамках пилотной стабилизации; не отправлять реальные API-запросы в тестах.
- Добавить mock-тесты выбора и повторного использования клиента, отсутствующего ключа, закрытия клиентов, передачи контекста/параметров Chat Completions, timeout, malformed response, cancellation, embeddings и выбранного провайдера в миграционном скрипте.
- Сохранить текущие внешние обращения; перед фактической миграцией API отдельно решить совместимость ProxiAPI, ZDR/retention, residency, стоимость и клиентские настройки.
- Пользовательский Excel с контрольными вопросами ожидается; автоматизированная оценка качества ответов остаётся незавершённой до его передачи.
- Настоящий файл окружения/секреты не читались и не включаются в отчёт.

**Статус:** этапы стабилизации пилота завершены. Полная миграция AI API не утверждена и не выполнялась. Jivo вебхуки и обработка событий остаются будущим отдельным этапом по требованию пользователя. Excel-набор вопросов ожидается; оценка качества ответов и настройка prompt по нему остаются открытыми.

### Выполненная реализация

- Асинхронные OpenAI-compatible клиенты переиспользуют HTTP-пулы, выбирают ключ и endpoint настроенного провайдера и закрываются при штатном останове приложения.
- Telegram polling запускается и контролируется через FastAPI lifespan; health сообщает о локальной готовности DB, индекса и polling без внешних платных вызовов. Webhook-режим отклоняется.
- История изолируется по Telegram chat/user, ограничивается двумя парами сообщений и TTL; один пользователь обрабатывается последовательно. Пустой текст, отсутствие индекса, пустой результат или сбой RAG не передаются в LLM.
- Аналитика работает вне ответа Telegram, ограничена 32 ожидающими задачами и 4 одновременными вызовами; при останове есть короткое окно на завершение.
- Telegram и админка используют один RAG singleton. FAISS поколения публикуются через атомарный `CURRENT`; индекс и метаданные проверяются перед переключением. Поиск не вызывает embeddings при отсутствии индекса.
- Jivo имеет выключенные по умолчанию настройки в админке; токены маскируются, пустая форма сохраняет dotenv/environment секреты, состояние хранится в `data/`. Webhook route пока возвращает HTTP 503.
- Админка проверяет bcrypt-хеш; state-changing POST маршруты требуют same-origin заголовок. AI-настройки меняются в runtime и сохраняются в смонтированный `.env`, который загружается заново при старте контейнера.
- Compose по умолчанию публикует приложение на localhost, хранит `data/`, `logs/`, `.env`, ограничивает CPU/RAM и журналы; Nginx доступен опционально и требует HTTPS до публичного запуска. Production Docker image строится на Python 3.11 slim Bookworm; зависимость bcrypt закреплена на совместимой с текущим Passlib версии.
- Миграционный скрипт использует ключ выбранного провайдера, создаёт backup текущего поколения, проверяет сохранённый индекс без выдуманного набора тестовых вопросов и завершается ненулевым кодом при ошибке.
