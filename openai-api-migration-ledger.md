# Журнал изменений AI-интеграции

**Приложение:** support_MAS — Telegram support bot, FastAPI, SQLite, FAISS.

**Текущие вызовы:** Chat Completions и embeddings `text-embedding-3-small` через общий пул асинхронных OpenAI-compatible клиентов для OpenAI или ProxiAPI.

**Модель ответов:** по новому указанию пользователя значение по умолчанию изменяется на `gpt-6-luna`. Официальная модель поддерживает Chat Completions и Responses; текущий этап сохраняет Chat Completions и задаёт `reasoning_effort=medium` и `max_completion_tokens` для GPT-6 Luna. Прежний `gpt-4.1-mini` остаётся примером legacy-модели.

**Сценарии:** ответы Telegram, query embeddings для RAG, embeddings аналитики; админский тестовый запрос. Инструментов и потоковой выдачи нет.

**Объём:** текущий дополнительный этап — сменить рабочую модель на `gpt-6-luna`, настроить совместимые с ней параметры Chat Completions и обновить документацию. Сохраняются OpenAI-compatible клиент, провайдеры, buffered text output, история и лимит `AI_MAX_TOKENS=800`; для иных моделей остаются прежние sampling-параметры и `max_tokens`. В версии SDK `openai==1.10.0` новые поля передаются через поддерживаемый `extra_body`. Responses API, streaming и server-side state не вводятся в этом узком этапе.

**Порядок:** предыдущие этапы стабилизации пилота завершены. Текущий этап — (7) переход default на GPT-6 Luna, совместимые параметры Chat Completions, обновление setup docs и mock-проверки. Следом — question-only проверка нового ответа по CSV после настройки ключа; Responses API, Jivo webhooks и другие более крупные изменения пока не входят в этот этап.

**Данные и приватность:** приложение хранит историю последних двух пар сообщений в памяти отдельно по паре Telegram chat/user, а вопросы и embeddings аналитики — в SQLite. В AI API отправляются текст вопроса, RAG-контекст и история. Новое серверное состояние Responses, кэширование приложения и срок удержания внешних данных не вводятся. Отдельное требование ZDR / региональной обработки пользователь не задавал; обработка внешним AI-провайдером зависит от проекта и выбранного маршрута.

**Проверки:** локальные проверки и тесты с mock-клиентами; реальные платные вызовы и боевой бот не запускались. Полный набор вопросов ожидает Excel.

## Оценка рекомендаций Responses API

OpenAI рекомендует Responses API для новых text-generation интеграций и указывает, что reasoning-модели обычно лучше работают через Responses. GPT-6 Luna при этом официально поддерживает `v1/chat/completions`, поэтому текущий этап сохраняет Chat Completions для минимального изменения приложения и поддержки имеющегося OpenAI-compatible client. ProxiAPI с новыми параметрами GPT-6 Luna отдельно не проверен. После получения ключа и проверки набора вопросов можно отдельно решить, нужен ли следующий этап Responses API. Источники: https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6 ; https://developers.openai.com/api/docs/models/gpt-6-luna .

## Принятые решения и валидация

- Установить GPT-6 Luna как default по прямому указанию пользователя; сохранить Chat Completions, оба провайдера и обычный текстовый ответ.
- Для GPT-6 Luna задавать medium reasoning и max completion budget 800; не передавать temperature/top_p, так как они не поддерживаются при reasoning effort, отличном от none. Frequency/presence penalties также не передаются, чтобы не зависеть от неподтверждённой model-specific поддержки. Для других моделей оставить все прежние legacy-параметры.
- Тесты кода используют mock-транспорт; дополнительно выполнена отдельная live-проверка OpenAI. Пользовательский CSV содержит 521 уникальный непустой вопрос; старые ответы и оценки не использовались.

- Добавить mock-тесты выбора и повторного использования клиента, отсутствующего ключа, закрытия клиентов, передачи контекста/параметров Chat Completions, timeout, malformed response, cancellation, embeddings и выбранного провайдера в миграционном скрипте.
- Сохранить текущие внешние обращения; ProxiAPI-совместимость новых GPT-6 параметров не подтверждена. ZDR/retention и региональную обработку не менять и не заявлять.
- CSV с 521 вопросом обработан: свежие ответы GPT-6 Luna сохранены отдельно; все запросы завершились без ошибок и для всех вопросов найден контекст. Старые ответы и оценки не использовались, автоматическая оценка качества не проводилась.

### Выполненная реализация

- Асинхронные OpenAI-compatible клиенты переиспользуют HTTP-пулы, выбирают ключ и endpoint настроенного провайдера и закрываются при штатном останове приложения.
- Telegram polling запускается и контролируется через FastAPI lifespan; health сообщает о локальной готовности DB, индекса и polling без внешних платных вызовов. Webhook-режим отклоняется.
- История изолируется по Telegram chat/user, ограничивается двумя парами сообщений и TTL; один пользователь обрабатывается последовательно. Пустой текст, отсутствие индекса, пустой результат или сбой RAG не передаются в LLM.
- Аналитика работает вне ответа Telegram, ограничена 32 ожидающими задачами и 4 одновременными вызовами; при останове есть короткое окно на завершение.
- Telegram и админка используют один RAG singleton. FAISS поколения публикуются через атомарный `CURRENT`; индекс и метаданные проверяются перед переключением. Поиск не вызывает embeddings при отсутствии индекса.
- Jivo имеет выключенные по умолчанию настройки в админке; токены маскируются, пустая форма сохраняет dotenv/environment секреты, состояние хранится в `data/`. Webhook route пока возвращает HTTP 503.
- Админка проверяет bcrypt-хеш; state-changing POST маршруты требуют same-origin заголовок. AI-настройки меняются в runtime и сохраняются в смонтированный `.env`, который загружается заново при старте контейнера.
- Compose по умолчанию публикует приложение на localhost, хранит `data/`, `logs/`, `.env`, ограничивает CPU/RAM и журналы; Nginx доступен опционально и требует HTTPS до публичного запуска. Production Docker image строится на Python 3.11 slim Bookworm; зависимость bcrypt закреплена на совместимой с текущим Passlib версии.
- Миграционный скрипт использует ключ выбранного провайдера, создаёт backup текущего поколения, проверяет сохранённый индекс без выдуманного набора тестовых вопросов и завершается ненулевым кодом при ошибке.

### GPT-6 Luna — параметры запроса и текущая проверка — 2026-11-10

- OpenAI docs подтверждают, что `gpt-6-luna` поддерживает `v1/chat/completions`; `reasoning_effort=medium` — модельное умолчание. При reasoning effort, отличном от `none`, Chat Completions нельзя передавать `temperature` и `top_p`.
- Legacy `frequency_penalty` / `presence_penalty` не документированы для этого GPT-6 режима как поддерживаемые; приложение опускает их, сохраняя для прежних моделей.

- Сохранён лимит 800 для совместимости; для GPT-6 Luna это общий предел на видимый ответ и reasoning tokens, поэтому видимая часть может стать короче.
- Пользователь вручную добавил ключ в `.env`; безопасная проверка подтвердила наличие без вывода значения. Live smoke request через `AIClient` завершился успешно.
- Индекс FAISS пересоздан из 117 фрагментов `knowledge_base.md` штатным кодом приложения. CSV обработан только по столбцу `Вопрос`: 521 свежий ответ, 0 ошибок API/поиска, 0 пустых контекстов. Выход: `Q-MAS-GPT6-Luna-results.csv`; старые ответы/оценки не читались для генерации или оценки.
