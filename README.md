# Нейро-техподдержка Школы Михаила Агеева

Бот поддержки с ответами по Markdown-базе знаний через RAG и FAISS. Модель по умолчанию в коде — `gpt-6.1-terra`, embeddings — `text-embedding-3-small`. Генерация и embeddings выполняются через API выбранного провайдера; локальная языковая модель не запускается.

Документация сверена с кодом **20 ноября 2026 года**.

## Возможности и ограничения

- Telegram работает через long polling. Команды: `/start` и `/clear_history`. Webhook-режим не реализован: запуск с `TELEGRAM_USE_WEBHOOK=true` отклоняется, endpoint возвращает HTTP 501.
- Админка позволяет просматривать уникальные вопросы, редактировать базу знаний, пересоздавать индекс, тестировать ответы и сохранять настройки AI и Jivo.
- Jivo: параметры сохраняются, но обработка событий **не реализована**. Даже при включении переключателя в админке endpoint `/api/jivo/webhook` возвращает HTTP 503.
- История разделена по паре чат/пользователь. По умолчанию сохраняются две полные пары вопрос/ответ до часа с последнего сохранённого обмена. История хранится в памяти и теряется при перезапуске.
- Лимит по умолчанию — 20 запросов на пару чат/пользователь за час; дополнительно действует фильтр спама. Аналитика записывается в фоне и при переполнении очереди может пропускать события.
- При остановке генерации по лимиту токенов выполняется один повтор с увеличенным бюджетом. Повторный обрыв заменяется сообщением о невозможности сформировать полный ответ. Длинные ответы Telegram отправляются последовательно частями до 4000 единиц UTF-16; пустые части пропускаются.
- Найденные фрагменты и история отделены от системных инструкций. Это снижает риск подмены правил, но не гарантирует отсутствие ошибок модели.

## Размер и требования

Измеренный размер локального образа `neuro-support:latest` на 19.11.2026 — **818 816 649 байт: около 819 МБ / 781 МиБ**. Это размер образа, а не RAM и не суммарное место Docker. Рабочие данные, логи, старые образы и кэш сборки занимают дополнительное место. Размер другой сборки может отличаться.

Ранее README указывал 6 ГБ, фиксированное потребление RAM и время сборки без воспроизводимых замеров. Эти значения не используются как характеристики текущей версии. В ранних зависимостях присутствовал `sentence-transformers`; сейчас его нет. `aiohttp` используется Telegram-клиентом и не заменён целиком на HTTPX.

Пилотная конфигурация рассчитана на сервер с 1 vCPU, 2 ГБ RAM и Ubuntu Server 24.04 без графического интерфейса. В Compose указаны лимиты приложения: 1 CPU и `1200M` памяти; это ограничения, а не измеренное потребление. Нагрузочная проверка на целевом сервере ещё не проводилась. Оставьте место для ОС, сборки, резервных копий и данных; ориентир — хотя бы 10 ГБ свободного диска.

Нужны Docker Engine с Compose plugin, SSH, Telegram Bot Token и ключ выбранного AI-провайдера. Требуется доступ к Telegram и AI API. Модель должна быть доступна выбранному аккаунту/провайдеру.

## Быстрый старт на Ubuntu

### 1. Подготовка

```bash
git clone https://github.com/AlexTagaev/support_MAS.git
cd support_MAS
cp .env.example .env
mkdir -p data/faiss_index logs
chmod 700 data logs
chmod 600 .env
```

Заполните `.env`: `TELEGRAM_BOT_TOKEN`, `ADMIN_USERNAME` и ключ провайдера. Хеш `ADMIN_PASSWORD_HASH` добавьте после следующего шага генерации. Для OpenAI используйте `LLM_PROVIDER=openai` и `OPENAI_API_KEY`; для ProxiAPI — `LLM_PROVIDER=proxiapi`, `PROXIAPI_API_KEY` и его base URL. Оставьте `TELEGRAM_USE_WEBHOOK=false`.

Соберите образ и получите bcrypt-хеш пароля админки:

```bash
docker compose build app
docker compose run --rm --no-deps app python -c 'from getpass import getpass; from passlib.context import CryptContext; print(CryptContext(schemes=["bcrypt"]).hash(getpass("Пароль админки: ")))'
```

В `.env` запишите полученный хеш в одинарных кавычках, чтобы символы `$` не интерпретировались Compose, например `ADMIN_PASSWORD_HASH='$2b$12$...'` (вместо многоточия нужен полный хеш). Время сборки зависит от сети, CPU и кэша.

### 2. Запуск и индекс

```bash
docker compose up -d app
```

Стандартный Compose публикует админку только на `127.0.0.1:8000`. На компьютере администратора откройте SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 <user>@<server-ip>
```

Откройте `http://localhost:8000/admin/`, войдите с логином и исходным паролем админки. В разделе «База знаний» нажмите «Пересоздать индексы». Это отправляет фрагменты базы провайдеру embeddings и расходует API-квоту. До создания индекса `/health` возвращает HTTP 503, а бот сообщает о временной неготовности.

Альтернатива для остановленного приложения:

```bash
docker compose stop app
docker compose run --rm --no-deps app python migrate_embeddings.py
docker compose up -d app
```

Скрипт обновляет файлы отдельным процессом. Для работающего приложения используйте кнопку в админке: она обновляет и индекс в памяти процесса.

Опциональный профиль `reverse-proxy` запускает Nginx на HTTP-порту 80. TLS в репозитории не настроен; публичную админку следует открывать только после настройки HTTPS. Порт 443 стандартным Compose не публикуется.

### 3. Готовность

```bash
curl -f http://localhost:8000/health
```

При успешной проверке:

```json
{"status":"healthy","version":"1.0.0","checks":{"database":"ok","faiss_index":"ok","telegram_polling":"ok"}}
```

Проверяются доступность БД, загруженный индекс и незавершённая задача polling. Это не проверка доступности внешнего AI API и не гарантия связи с Telegram. При неготовности возвращается HTTP 503 с результатами в `detail`.

Поле версии API сейчас равно `1.0.0`, а метка Docker — `2.0.0-refactored`; они не синхронизированы. Для идентификации сборки используйте Git-коммит и ID образа.

## Конфигурация

Значения по умолчанию определены в [app/config.py](app/config.py); пример — [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `openai` | `openai` или `proxiapi` |
| `OPENAI_API_KEY` | пусто | Нужен для OpenAI |
| `OPENAI_API_BASE` | не задан | Необязательный base URL |
| `PROXIAPI_API_KEY` | не задан | Нужен для ProxiAPI |
| `PROXIAPI_API_BASE` | `https://api.proxyapi.ru/openai/v1` | Base URL ProxiAPI |
| `TELEGRAM_BOT_TOKEN` | без значения | Обязательный токен бота |
| `TELEGRAM_USE_WEBHOOK` | `false` | Поддерживается только `false` |
| `TELEGRAM_WEBHOOK_URL` | не задан | Поле зарезервировано, webhook не работает |
| `ADMIN_USERNAME` | `admin` | Логин Basic Auth |
| `ADMIN_PASSWORD_HASH` | пусто | Для входа нужен bcrypt-хеш |
| `AI_MODEL` | `gpt-6.1-terra` | Модель генерации |
| `AI_MAX_TOKENS` | `800` | Начальный бюджет генерации |
| `AI_TEMPERATURE` / `AI_TOP_P` | `0.7` / `0.9` | Legacy-параметры; для GPT-6.1 Terra не отправляются |
| `KNOWLEDGE_BASE_PATH` | `data/knowledge_base.md` | Файл базы |
| `FAISS_INDEX_PATH` | `data/faiss_index` | Каталог индекса |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1000` / `200` | Размер в символах; перекрытие применяется при резервном разбиении длинного сегмента |
| `TOP_K_RESULTS` | `3` | Максимум найденных фрагментов |
| `RAG_MIN_SIMILARITY` | `0.25` | Минимальная косинусная близость при поиске |
| `SIMILARITY_THRESHOLD` | `0.85` | Порог объединения вопросов в аналитике |
| `RATE_LIMIT_REQUESTS` / `RATE_LIMIT_WINDOW` | `20` / `3600` | Запросы за окно в секундах |
| `MAX_CONTEXT_MESSAGES` | `5` | Округляется до полных пар: по умолчанию 4 сообщения |
| `CONTEXT_TTL` | `3600` | Срок истории в секундах |
| `JIVO_BOT_TOKEN` / `JIVO_WEBHOOK_SECRET` | не заданы | Исходные параметры Jivo, без активации обработки |
| `DEBUG` / `LOG_LEVEL` | `false` / `INFO` | Отладка и логирование |

Для моделей с префиксом `gpt-6-luna` или `gpt-6.1-terra` клиент отправляет Chat Completions с `reasoning_effort=medium` и `max_completion_tokens`, без legacy sampling/penalty-параметров. Бюджет включает видимые и reasoning-токены. При `finish_reason=length` повтор использует `max(2 * AI_MAX_TOKENS, 3200)`, что может увеличить задержку и стоимость. Для других имён моделей код отправляет legacy-параметры; произвольная замена модели не гарантирует совместимость. ProxiAPI с GPT-6.1 Terra отдельно не проверялся.

Порог поиска `0.25` предварительный, а не оценка достоверности ответа. Он отличается от порога аналитики `0.85`. При пустом результате Telegram просит уточнить запрос, не вызывая генерацию; тестовый API админки возвращает HTTP 422.

## Админка и хранение данных

| Раздел | Адрес | Возможности |
|---|---|---|
| Аналитика | `/admin/` | Уникальные вопросы, источник, даты, повторения |
| База знаний | `/admin/knowledge` | Редактирование и отдельная пересборка индекса |
| Тестирование | `/admin/test` | Ответ и найденный контекст без отправки в Telegram |
| Настройки | `/admin/settings` | AI-провайдер, ключи, модель и подготовка Jivo |

AI-настройки сохраняются в смонтированный `.env` и применяются в текущем процессе. После смены провайдера или endpoint embeddings пересоздайте индекс через админку: индекс не хранит сведения о провайдере, а одинаковое имя модели не гарантирует совместимость векторов. Сохранённые embeddings аналитики также автоматически не пересчитываются; их миграцию нужно планировать отдельно. Jivo хранится отдельно в `data/integration_settings.json`; файл содержит секреты. Его путь можно изменить через переменную окружения процесса `INTEGRATION_SETTINGS_PATH`. Сохранение переключателя Jivo не включает обработку вебхуков.

```text
app/
  admin/          # Routes, Basic Auth, шаблоны, настройки интеграций
  core/           # AI-клиент, провайдеры, поиск, история, лимиты
  database/       # SQLite / SQLAlchemy async и аналитика вопросов
  integrations/   # Telegram и заглушка Jivo
  utils/          # Логирование
  config.py       # Настройки
  main.py         # FastAPI и lifecycle
data/
  knowledge_base.md
  database.db
  integration_settings.json
  faiss_index/
    CURRENT
    generations/<id>/index.faiss
    generations/<id>/metadata.json
logs/
docs/             # Результаты проверки и архив прежних инструкций
tests/
```

Compose монтирует `data/`, `logs/` и `.env`. Рабочие БД, индекс, настройки интеграций и секреты исключены из Git. База знаний отслеживается в Git: изменения через админку меняют локальный файл и могут конфликтовать с обновлением репозитория.

После правок базы или алгоритма разбиения пересоздайте индекс. Новая генерация публикуется атомарно; старые поколения автоматически не удаляются. Legacy-индекс из корня каталога читается для совместимости, векторы нормализуются в памяти. Архив `docs/archive/` в поиск не входит. Сведения, требующие подтверждения, перечислены в [docs/knowledge-review.md](docs/knowledge-review.md).

## Мониторинг и диагностика

```bash
docker compose logs -f app
docker stats neuro-support
docker image inspect neuro-support:latest --format '{{.Size}}'
docker system df
```

`docker system df` показывает также другие образы, контейнеры, тома и кэш; это не размер одного приложения. Файловые логи находятся в `logs/app.log`: JSON, ротация 100 МБ, хранение 30 дней, ZIP. Отдельный Docker-журнал ограничен тремя файлами по 10 МБ; это не ограничивает каталог файловых логов.

- **Бот не отвечает:** проверьте `/health`, наличие индекса, токен, сеть и отсутствие второго процесса polling с тем же токеном. При старте приложение само сбрасывает webhook. По логам `rag_ms`, `llm_ms`, `send_ms`, `total_ms` можно определить этап задержки.
- **Сеть Telegram:** до трёх попыток отправки каждой части; паузы между попытками — 1 и 2 секунды, timeout запроса — 60 секунд. Причину задержки нужно определять по логам, а не считать любой сбой сетевой проблемой.
- **Оборванный ответ:** ищите `AI response reached token limit` и `AI response still incomplete after retry`. Проверьте, что запущен обновлённый образ с обработкой `finish_reason`.
- **Нет релевантных фрагментов:** проверьте содержание базы, `CURRENT` и соответствующее поколение индекса. Настраивайте `TOP_K_RESULTS` и порог на проверочных вопросах; увеличение числа фрагментов не исправляет отсутствие фактов.
- **OOM:** проверьте `docker stats`, состояние контейнера и логи. Не поднимайте лимит до 4 ГБ на сервере с 2 ГБ RAM. Уменьшение `CHUNK_SIZE` может увеличить число векторов; оно не гарантирует экономию памяти. Увеличение ресурсов требует соответствующей памяти сервера.
- **Ошибки AI API:** проверьте выбранного провайдера, доступ к модели, квоту и ключ именно этого провайдера. Не публикуйте ключи в логах или обращениях.
- **Повторная авторизация админки:** нужен исходный пароль, соответствующий bcrypt-хешу. Проверьте кавычки вокруг хеша в `.env`. После ручного изменения настроек пересоздайте контейнер, когда допустим перерыв в работе.
- **Ошибка запуска:** проверьте `.env`, логи и порт 8000 на localhost. Порт 80 нужен только профилю Nginx. `docker compose config --no-env-resolution --quiet` проверяет конфигурацию без вывода значений секретов.

## Резервное копирование и обновление

Следующие команды останавливают или пересоздают приложение и прерывают работу бота. Выполняйте их в согласованное окно обслуживания.

Перед обновлением сохраните рабочие данные. Архив содержит секреты:

```bash
umask 077
docker compose stop app
tar -czf ../support-data-$(date +%F-%H%M%S).tar.gz data logs .env
docker compose start app
```

Для обновления кода сначала проверьте `git status`: изменения базы через админку нужно сохранить и согласовать с версией Git. Не выполняйте принудительный сброс рабочего файла.

```bash
git switch main
git pull --ff-only origin main
docker compose build app
docker compose up -d --no-deps app
```

Если база или алгоритм поиска изменились, пересоздайте индекс в админке. Затем проверьте `/health` и ответ бота. Обычный `docker compose restart` не заменяет контейнер новым образом. История диалогов после пересоздания теряется.

Для редактирования базы достаточно сохранить файл через админку или локально, затем вызвать пересборку в админке. CLI-миграцию запускайте только при остановленном приложении, как описано в быстром старте.

## Разработка и проверки

Проверяемое окружение — Python 3.11. Не запускайте разработческий процесс одновременно с рабочим ботом на одном Telegram-токене.

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q tests
```

Для запуска приложения после заполнения `.env`:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Тестовые зависимости не входят в production-образ. Последний полный прогон на 20.11.2026: **52 теста прошли** в Docker. Есть предупреждения об устаревающих интерфейсах зависимостей. После правок содержания выполнены 18 выборочных проверок реального API; это не оценка точности на всей выборке. Прежние 521 ответ получены до содержательных изменений, полный повторный прогон не выполнен. Нагрузка на целевом VPS и полный цикл доставки в Telegram этим тестированием не подтверждены.

## Переход на GPT-6.1 Terra — 20.11.2026

Доступ к Terra проверен реальным запросом с ключом проекта. Приложение развёрнуто на сервере: `/health` возвращает HTTP 200, два проверочных вопроса через RAG получили законченные ответы. Индекс и модель embeddings при переходе не менялись. Предыдущий образ сохранён на сервере как `neuro-support:before-terra`. Эти проверки не заменяют полную оценку качества на тестовой выборке.

## Изменения текущей версии

- Модель по умолчанию GPT-6.1 Terra; совместимые параметры запросов и повтор при обрыве.
- Промпт и факты разделены; уточнены сертификат/диплом, датированные сведения и авторские утверждения.
- Заголовки сохраняются в фрагментах; поиск фильтруется по косинусной близости.
- Улучшены жизненный цикл индекса, история Telegram, фоновая аналитика и локальная проверка готовности.
- Настройки Jivo доступны в админке; вебхуки остаются отдельной будущей задачей.

Подробности: [журнал AI-интеграции](openai-api-migration-ledger.md) и [проверка базы знаний](docs/knowledge-review.md). История коммитов служит источником дат изменений; неподтверждённые сравнения размера, RAM и скорости удалены из документации.
